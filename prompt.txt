═══════════════════════════════════════════════════════════════════
CRYPTOGRAPHIC IMPLEMENTATION
═══════════════════════════════════════════════════════════════════

SHA-256 Hashing:
  - Chunk-based (8192 bytes) for large files
  - Return hex digest

RSA-2048:
  - Key generation on user registration
  - Sign: hash digest (not raw file)
  - Verify: signature against hash
  - Store: PEM format (private key encrypted with user password-derived key)

AES-256-GCM:
  - Encrypt all files before storage
  - Key derivation: PBKDF2-SHA256 (100k iterations)
  - Unique IV (12 bytes) per file
  - Store: IV + ciphertext + tag

═══════════════════════════════════════════════════════════════════
VERIFICATION WORKFLOW (MANDATORY LOGIC)
═══════════════════════════════════════════════════════════════════

1. Validate file_id exists in DB
2. Check user permissions
3. Load file metadata (hash, signature, encrypted_path)
4. Read encrypted file from storage
5. Decrypt using AES-256-GCM
6. Recompute SHA-256 (chunk-based)
7. Compare: computed_hash vs stored_hash → hash_match
8. Verify RSA signature using public key → signature_valid
9. Determine: verified = hash_match AND signature_valid
10. Save verification record to DB
11. Update file.last_verified, file.verification_count
12. Log audit event
13. Return {verified, hash_match, signature_valid, tampered, timestamp}
